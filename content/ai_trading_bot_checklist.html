The AI Trading Bot Checklist.

From idea to live deployment, with prompting strategies for AI-assisted development. The practical guide for builders who want their bot to survive the real market.

11 phases · 90+ items · click to check off as you go

// before you start

Most trading bots fail. Not because the strategy was wrong, but because the operational side got ignored. This checklist covers everything that actually matters, including how to prompt AI effectively when you're building most of the code with help from Claude, ChatGPT, or similar tools.

Work through each phase in order. Skipping ahead is how bots lose money.

phase_01

Strategy and foundation

Define your trading approach

  • Identify the market you'll trade (crypto, forex, stocks, futures)
  • Choose your strategy type (trend-following, mean reversion, arbitrage, market making, momentum)
  • Define your time frame (scalping, day trading, swing, long-term)
  • Set clear entry and exit criteria
  • Document your risk tolerance and maximum drawdown

Set realistic expectations

  • Calculate target returns based on strategy
  • Define what success looks like for your bot
  • Accept that most bots fail in live trading even when they backtest well
  • Plan for 6 to 12 months of refinement before expecting consistent results
phase_02

Data and research

Data acquisition

  • Source historical market data (clean, complete, high quality)
  • Identify data providers (Binance API, Alpha Vantage, Polygon, IEX, CCXT)
  • Ensure data covers different market conditions (bull, bear, sideways, high volatility)
  • Plan for real-time data feeds for live trading
  • Build a data validation pipeline to catch missing or corrupted data

Feature engineering

  • Decide which technical indicators to use (RSI, MACD, moving averages, volume)
  • Consider fundamental data if relevant
  • Include sentiment analysis (news, social media) if applicable
  • Engineer custom features specific to your strategy
  • Test feature importance before including them
phase_03

AI architecture (SOLID)

Design for extensibility from day one. You'll thank yourself later.

Design with extensibility in mind

  • Define interfaces for data sources so you can swap providers later
  • Create interfaces for strategy execution so different strategies plug in
  • Build interfaces for risk management modules
  • Separate concerns: data layer, strategy layer, execution layer, monitoring layer
  • Use dependency injection so components can be tested independently

Choose your AI approach

  • Decide between supervised learning, reinforcement learning, or ensemble methods
  • Consider model types: LSTM, transformers, random forests, XGBoost, neural networks
  • Start simple before going complex (a basic model often beats overfit complex ones)
  • Plan for model versioning and rollback capability

Model training

  • Split data properly (train, validation, test, ideally with walk-forward analysis)
  • Avoid look-ahead bias at all costs
  • Handle class imbalance if predicting direction
  • Cross-validate across different market regimes
  • Document hyperparameters and training conditions
phase_04

Prompting AI to build your code

This is the section most people get wrong. If you're using AI to build the majority of your bot, how you prompt determines whether you end up with clean, extensible code or a tangled mess you can't maintain.

Start with architecture, not code

Before asking AI to write a single line, prompt it to design the structure first.

"I want to build a trading bot for [market] using [strategy]. Before writing any code, design the architecture using SOLID principles. Show me the main interfaces, classes, and how they interact. Explain how each component can be extended later without breaking the others."

Get the AI to commit to the architecture before generating implementations. This prevents tightly coupled code that becomes impossible to modify.

Define your interfaces first

Ask the AI to write the interfaces (abstract base classes in Python, interfaces in TypeScript) before any concrete implementations.

"Write the interfaces for: DataProvider, Strategy, RiskManager, OrderExecutor, and PerformanceTracker. Each should be designed so I can have multiple implementations later. Include docstrings explaining the contract each interface enforces."

Provide context aggressively

AI generates better code when it knows the full picture. Include:

  • Your overall goal and strategy
  • The languages and libraries you're using
  • Existing code (paste it in, don't just describe it)
  • Constraints (latency, broker API limits, data format)
  • The SOLID principle you want enforced

Prompt for one component at a time

Don't ask for the entire bot in one prompt. You'll get something that looks impressive but is impossible to debug.

"Now implement the BinanceDataProvider class that conforms to the DataProvider interface we defined earlier. It should handle rate limiting, automatic reconnection, and return data in the format the interface specifies."

The prompting pattern for new strategies

When you have a strategy idea and want AI to build it, use this template:

1. Context: "I'm building a [type] trading bot for [market]."
2. Goal: "I want to test this strategy: [describe in plain English]."
3. Constraints: "It must follow SOLID principles, depend on the Strategy interface, and not couple to any specific data provider."
4. Output: "Return only the strategy class and its unit tests."
5. Verify: "Explain how each SOLID principle was applied."

Force the AI to explain its decisions

After receiving code, prompt it to justify the design:

"Walk me through this code. Explain why you structured it this way, what could break it, and where I'd extend it to add [feature]."

If the AI can't explain it cleanly, the code is probably bad.

Ask for tests with every component

Always include this in your prompts:

"Include unit tests using pytest. Mock external dependencies. Test edge cases including: empty data, malformed data, network failures, and rate limit errors."

Use AI to review its own code

After getting an implementation, start a fresh conversation and prompt:

"Review this trading bot code. Look for: violations of SOLID principles, security issues with API keys, missing error handling, race conditions, and any way this could lose money unexpectedly."

Watch for these AI mistakes

  • Hardcoded values that should be configuration
  • Direct API calls inside strategy logic (breaks dependency inversion)
  • Missing error handling on network requests
  • No logging of decisions
  • Tightly coupled classes that import each other
  • Magic numbers without explanation
  • Synchronous code where async is needed
  • No input validation on market data

Build your prompting library

Save prompts that work. You'll reuse them constantly:

  • Strategy implementation prompt
  • Risk module prompt
  • Backtest engine prompt
  • Error handling review prompt
  • Security audit prompt
phase_05

Backtesting

Build a robust backtest engine

  • Include realistic slippage estimates
  • Account for trading fees and commissions
  • Model spread costs accurately
  • Include market impact for larger orders
  • Test on out-of-sample data the model has never seen

Validate results

  • Calculate Sharpe ratio, Sortino ratio, max drawdown
  • Check win rate vs risk-reward ratio
  • Analyze performance across different market conditions
  • Look for signs of overfitting
  • Test on multiple instruments if strategy claims to be universal
phase_06

Risk management

Position sizing

  • Implement Kelly Criterion or fixed fractional sizing
  • Set maximum position size per trade
  • Define maximum concurrent positions
  • Account for correlation between positions

Stop losses and circuit breakers

  • Hard stop loss on every trade
  • Daily loss limit (bot stops trading if hit)
  • Weekly and monthly drawdown limits
  • Maximum consecutive losses trigger
  • Volatility-based position sizing adjustments

System safeguards

  • Kill switch (manual override to halt all trading)
  • Automatic shutdown on unusual behavior
  • Maximum order size limits
  • Sanity checks on every order before submission
  • Anomaly detection on bot behavior
phase_07

Infrastructure and deployment

Hosting and reliability

  • Choose cloud provider (AWS, GCP, Azure, or VPS)
  • Set up redundancy (failover servers)
  • Plan for low latency if needed (co-location for HFT)
  • Ensure 24/7 uptime monitoring
  • Backup systems for critical components

Security

  • Store API keys in secure vault (never in code)
  • Use IP whitelisting on exchange APIs
  • Enable 2FA on all accounts
  • Use read-only keys where possible
  • Encrypt data at rest and in transit
  • Regular security audits

Code quality

  • Write unit tests for all critical components
  • Integration tests for the full pipeline
  • Use version control with proper branching strategy
  • Code reviews before deploying changes
  • CI/CD pipeline for safe deployments
phase_08

Paper trading

Test in live conditions without real money on the line.

  • Run the bot on paper trading for at least 1 to 3 months
  • Compare paper results to backtest results (gaps reveal problems)
  • Test during high volatility events
  • Verify order execution latency
  • Confirm data feeds work reliably 24/7
phase_09

Going live

Start small

  • Begin with minimum capital you can afford to lose
  • Use a fraction of intended position sizes initially
  • Monitor closely for the first few weeks
  • Compare live performance to paper trading
  • Scale up gradually as confidence builds

Logging and monitoring

  • Log every trade, signal, and decision
  • Real-time performance dashboard
  • Alert system for unusual events (Telegram, email, SMS)
  • Daily performance reports
  • Track latency, slippage, and execution quality
phase_10

Maintenance and iteration

Ongoing operations

  • Monitor for strategy decay (markets change)
  • Regular retraining schedule for ML models
  • Watch for regime changes that might break the strategy
  • Update data pipelines as APIs change
  • Keep dependencies and libraries updated

Continuous improvement

  • Analyze losing trades for patterns
  • A/B test strategy variations on paper
  • Document every change and its impact
  • Build a research backlog for future improvements
  • Stay current with new research and techniques
phase_11

Legal and compliance

Cover yourself

  • Check regulations in your jurisdiction (Australia has specific rules)
  • Understand tax implications of automated trading
  • Keep detailed records for ATO reporting
  • Review broker or exchange terms of service for bot usage
  • Consider business structure if scaling significantly

Documentation

  • Document the strategy thoroughly
  • Keep records of all backtests and decisions
  • Maintain audit trail of code changes
  • Document risk management rules
  • Create runbooks for common issues
// critical warnings

Read these before you deploy anything

  • Most retail trading bots lose money. Be prepared for this.
  • Never trade with money you can't afford to lose.
  • Past performance does not guarantee future results.
  • Overfitting is the silent killer of trading bots.
  • The market doesn't care about your code's elegance.
  • AI can write code fast, but it can't tell you if your strategy will work in real markets.
